## Router 路由

### 🟢 next / replace / hash

- `next('/')` = `next({ path: '/' })`，对象形式可带 `query`/`replace`
- **path 和 params 互斥**，一起传 params 会丢
- `replace: true` = 替换历史记录不追加，不是"确保成功"
- hash 模式 URL 带 `#`，history 模式需服务器重定向

### 🟡 导航守卫顺序

> ❌ 记成：`...→ beforeEnter → afterEach → beforeRouteEnter`；漏了 beforeResolve

**正确**：`Leave → Each → Update → Enter → 异步组件 → RouteEnter → Resolve → 确认 → After`

### 🟢 路由匹配优先级

先注册先匹配，404 最后加。

## 原型链

### 🟢 instanceof

> ❌ 记成 `foo.prototype.__proto__`

沿**实例的 `__proto__`** 往上爬，碰到 `Constructor.prototype` 即真。`null` 没有 `__proto__` 返回 false。

三条：`fn → Function.prototype → Object.prototype → null`；`obj → Foo.prototype → Object.prototype → null`；`Function.__proto__ === Function.prototype`

## HTTP 缓存 🟢

> ❌ 协商返回 304 不是 200；强缓存命中无请求无响应；no-cache 是问服务器

强缓存不请求直接读本地；协商发请求服务器决定；F5 跳强缓存走协商；Ctrl+F5 全部跳过。

max-age(相对) > Expires(绝对)；ETag(指纹) > Last-Modified(时间)。

## Node.js 深入 + React 基础 + 算法手写（5/18 Day7）

### Node.js

**🟢 app.use vs app.get/post**：`app.use` 拦截所有方法，`app.get/post` 只拦截对应方法；按代码顺序执行，先过 `cors()` → 再过 `express.json()` → 再到具体路由

**🟢 express.json()**：全局中间件，把请求 body 的 JSON 字符串解析为 `req.body` 对象（任何方法都过，但 body 只对 POST/PUT/PATCH 有意义）

**🔴 异常处理四参数**：`(err, req, res, next)` — 前面路由调 `next(err)` 或抛异常时被截住。四参数是 Express 用来区分异常处理器的标识，不是三参数的一般中间件

### React 基础（对照 Vue）

**🟢 JSX 三条规则**：必须有根元素 / `{}` 内可写任意 JS 表达式 / 属性名驼峰（`className`、`onClick`）

**🟢 React 父/子通信 vs Vue**：React 没有 `$emit`，子调父 = 父把回调函数通过 props 传下去；模板和逻辑在同一个函数 return 返回；无语法糖（v-model/v-for 展开为手动 JS）

**🟡 zustand set/get**：`set` = Pinia action 里改 state 触发渲染；`get` = 读最新值。和 Vue 的 getter/setter 不同 — zustand 没有响应式系统，需要手动 `set({ count: 1 })` 才能触发重渲染。唯一 store 名字拼写成 `useStore` 需要用 `useDesignerStore` 表示是从 zustand store 来的

### 算法手写

**🟢 Promise.retry**：递归 `attempt(n)`，`fn()` 成功直接 resolve → 失败判断 `n <= 1` 结束失败 → 还有次数再递归 `attempt(n - 1)`；和 `defineAsyncComponent` 的 `onError(retry, fail)` 同一个模式

**🟢 Promise 并发调度器**：`limit`(并发上限) / `running`(当前几个在跑) / `index`(下一个该谁跑) → 队列 + `finally` 里 `running--` 再调 `next()` 补位

## 虚拟滚动 + 树与数组互转（5/18 Day7）

### 🟡 虚拟滚动

**核心**：只渲染可视区内的节点，其余用 phantom 占位撑开滚动条

| 变量 | 公式 | 作用 |
|---|---|---|
| `startIndex` | `Math.floor(scrollTop / itemHeight)` | 从第几条开始渲染 |
| `visibleCount` | `Math.ceil(viewHeight / itemHeight)` | 屏幕可见几条 |
| `endIndex` | `startIndex + visibleCount` | 渲染到第几条 |
| `offsetY` | `startIndex * itemHeight` | 偏移量（translateY） |
| `phantomHeight` | `totalCount * itemHeight` | 撑开滚动条 |

> ❌ 记错：offsetY = startIndex * 项目宽度（应为 itemHeight）；漏了 phantomHeight

### 🟡 树与数组互转

**arrToTree**：Map + parentId 一次遍历，找到父节点塞入 children，无父节点 = 根节点

**treeToArr**：队列/栈遍历树，把嵌套节点推平到一维数组

> ❌ 记错：arrToTree = 层序遍历（实际是 Map + parentId）
